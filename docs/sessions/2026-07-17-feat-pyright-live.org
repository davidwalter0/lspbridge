* Decisions Made
- Installed pyright via npm, pinned to the exact current-stable version
  (1.1.411) rather than `latest` — `npm view pyright version` first, then
  `npm install -g pyright@1.1.411`.
- DiagnosticsCollector.Wait polls (50ms) for a *non-empty* diagnostics batch
  rather than returning on the first publishDiagnostics notification: some
  servers publish an interim empty batch before the real one, and returning
  too early would make the live test flaky. Poll-based (not goroutine+cond)
  to avoid a leaked goroutine when the caller's ctx of Wait is never itself
  canceled.
- PyrightSpec resolves the binary via exec.LookPath up front so a missing
  install fails with a clear "executable file not found in $PATH" error
  rather than a generic Launch failure, and so the live test's skip check
  (`exec.LookPath(PyrightCommand)`) and the Spec construction share one
  source of truth for the binary name.
- Kept the pyright preset inside pkg/server (pyright.go) rather than a new
  pkg/servers package — one server for now, minimal footprint; revisit if/when
  tsserver / rust-analyzer presets are added in a later increment.
- Live test lives in pkg/server (not a new pkg/live) since it only exercises
  Launch + Client + the lsp.DiagnosticsCollector handler — no new seam needed.

* Glossary
- publishDiagnostics :: the LSP server→client notification
  (`textDocument/publishDiagnostics`) a server sends, unprompted, whenever a
  document's diagnostics change; unlike most LSP traffic it has no request ID
  and arrives on the jsonrpc.Handler notification path.
- DiagnosticsCollector :: pkg/lsp's jsonrpc.Handler that records the latest
  publishDiagnostics batch per URI and offers a blocking Wait(ctx, uri).
- PyrightSpec :: pkg/server's Spec preset for launching
  `pyright-langserver --stdio`, resolved via PATH.
