* Decisions Made
- *=RequireMarker= as a new =MarkerResolver= field, not a new resolver type.*
  Every prior MarkerResolver-based preset (Python/TS/JS/Rust) is correctly
  claimed by extension alone — a .py file is Python whether or not
  pyrightconfig.json exists anywhere above it. Angular's ".html" breaks that
  assumption: plain HTML is not inherently Angular. Reusing the existing
  optional-field extension pattern (the precedent =LanguageFor= set) keeps
  the FindUp/marker-walk logic in one place and leaves every existing
  preset's behavior byte-for-byte unchanged (RequireMarker's zero value is
  false).
- *Angular languageId is "html", not "angular" — verified against the
  installed server's own source, not just docs.* The task flagged this as
  ambiguous. WebFetch of https://angular.dev/tools/language-service and
  https://emacs-lsp.github.io/lsp-mode/page/lsp-angular/ both pointed at
  "html"/"typescript"/"ts", but the strongest evidence was grepping the
  actual installed (if incomplete) @angular/language-server v20.0.1 source
  on this host: its internal LanguageId enum defines exactly two values,
  TS="typescript" and HTML="html", and its didOpen/documentSymbol handling
  keys off `params.textDocument.uri.endsWith(".html")`. "angular" appears
  nowhere as an LSP languageId in that chain.
- *Angular probe-location args point at the workspace root (dir), not
  dir/node_modules.* Verified two ways: (1) reading the installed server's
  bundled resolver — it calls Node's `require.resolve(pkg, {paths:
  [location]})`, and Node's own semantics treat each path as a *starting
  point* for an upward node_modules walk, not a literal node_modules
  directory; (2) a live probe on this host: passing the literal
  ~/.npm-global/lib/node_modules directory as --tsProbeLocations resolved
  typescript successfully (via the upward-walk landing on its parent's
  node_modules), confirming the mechanism empirically, not just by reading
  code.
- *Discovered but did NOT use a stray Angular Language Server install.*
  `which ngserver` resolved to ~/.npm-global/bin/ngserver (a real symlink to
  a real @angular/language-server v20.0.1 install, bin dated May 2025) —
  contradicting the task's premise that it's "not installed." Investigated
  rather than trusting either the premise or the surprise finding blindly:
  actually running it (with correct --tsProbeLocations/--ngProbeLocations)
  fails with `Error: Failed to resolve '@angular/language-service' with
  minimum version '15.0'` — that peer package is genuinely absent, and the
  install's age/location suggest unrelated leftover state rather than
  something provisioned for this ecosystem. Conclusion: honor the task's "no
  live test" framing (this install can't produce one anyway) rather than
  quietly expanding scope to install the missing peer, which the task didn't
  ask for. Reported the finding transparently instead of silently ignoring
  it or silently treating it as "installed."
- *Generalized =missingBinaryError= to (cmd, exttoolName, err) rather than
  duplicating the error-format string in angular.go.* Angular is the first
  preset where the LookPath'd binary name ("ngserver") and exttool's
  package-derived tool name ("angular-language-server") differ. A DRY
  two-parameter helper (defaulting to "pass cmd for both" for every
  pre-existing preset) was lower-risk than forking the format string, and
  the two existing call sites were updated and reverified against their
  existing tests (byte-identical error text).
- *Dart's live test needed no fixture iteration.* Unlike rust-analyzer (up
  to 90s cold-index wait budgeted), the Dart Analysis Server answered
  documentSymbol for a tiny pubspec.yaml package in 0.15s with no visible
  warm-up delay. The generous-timeout/honest-skip pattern is implemented
  anyway (matching the task's explicit caution and this package's
  established convention for the other two "live-with-indexing" servers),
  but it never triggered on this host.
- *No pyright.go retrofit.* Same call as the prior session: out of scope,
  keeps the diff minimal.

* Glossary
- RequireMarker :: MarkerResolver's optional field making a discoverable
  marker mandatory; when true, Resolve reports no match at all instead of
  falling back to the file's own directory
- probe location :: an Angular Language Server CLI arg (--tsProbeLocations /
  --ngProbeLocations) naming a directory Node's require.resolve treats as an
  upward-search starting point for a required peer package
- ngserver :: the Angular Language Server's installed binary name (npm
  package @angular/language-server); differs from exttool's tool-name slug
  "angular-language-server"
- pub package :: a Dart/Flutter package rooted at pubspec.yaml; the marker
  DartResolver walks up for
