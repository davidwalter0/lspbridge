* Session Topic
Build the WRITE-path adapter for lspbridge (mgmt f51cf319, P0.2): map an LSP
=WorkspaceEdit= to an ae-consumable edit plan, deciding dependency direction so
lspbridge's zero-dependency, CGO_ENABLED=0 invariant is preserved.

* Decisions Made
- *Neutral representation, ae adapts FROM it* (NOT hard-import ae). ae's
  =pkg/transaction= is cgo-free and internally light (only depends on
  stdlib-only =docmutator=), BUT importing it drags mcp-agent-editor's whole
  go.mod require-graph (smacker/tree-sitter, postgresql-parser, go-sdk, …) into
  lspbridge's go.sum and bumps its go floor 1.25→1.26.5, destroying the
  "no external deps" keystone property. So lspbridge owns a neutral byte-offset
  =Plan=; ae converts offset→unified-diff on its side (where go-difflib already
  lives). Arrow points heavy→light. Full rationale: docs/design/wsedit-ae-seam.org.
- ae represents an edit as a *unified diff* (=FileChange.UnifiedDiff=, difflib
  Context:3), not offset+replacement — reinforces the offset seam (don't make the
  bridge reproduce difflib framing for the strict =ApplyUnifiedDiff= staleness gate).
- *Byte-offset addressing*: half-open [Start,End) into original bytes; edits
  stored DESCENDING by Start so left-to-right apply never invalidates a lower
  offset; overlaps rejected at construction, re-checked defensively in Apply.
- *Coordinate conversion*: LSP Position (0-idx line, UTF-16 code-unit char) →
  UTF-8 byte offset needs file content. Walk to line start (split on \n, \r of
  \r\n is terminator not text), count UTF-16 units (1 BMP / 2 astral). Clamp:
  char past line end → line end; mid-surrogate → rune start (never split a rune).
- Neutral DTO (=plan.go=) imports neither ae nor =pkg/lsp=; only =convert.go=
  is LSP-aware — a clean seam ae can copy the shape of without pulling pkg/lsp.

- WorkspaceEdit :: LSP's map of DocumentURI → []TextEdit; a server computes it

  contract ae adapts from.

- ByteOffset :: LSP (line, UTF-16 char) → UTF-8 byte offset, content-dependent.
