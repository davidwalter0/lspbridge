* Session Topic
Give the =lspbroker= daemon an owner: a systemd =--user= unit (materialize
only, never activate), install/uninstall Make targets, and a =make doctor=
diagnostic that catches the specific outage class that made the semantic
tier look absent for a multi-day session — a socket-path mismatch between
the daemon's default and what mcp-ast/ae actually dial, PLUS (added
mid-task) a null-response ambiguity that can make a WORKING daemon look
broken even once the path is right.

* Decisions Made
- *Plain always-on service, not socket activation.* =lspbroker= has no
  =LISTEN_FDS= handling (verified by reading =cmd/lspbroker/main.go= and
  =pkg/broker/socket.go= in full); =Accept=no= would hand it descriptors it
  ignores. Socket activation stays a documented future option, not
  implemented here. See design doc §3.
- *The socket path is pinned explicitly in the unit*, computed from a
  literal =/tmp=-rooted formula in the Makefile, cross-checked by
  =cmd/lspdoctor='s independently-derived value (never a hand-copied
  formula in two places that can drift). See design doc §4.
- *=Environment=PATH=__PATH__= is captured from the installing shell*, not
  invented — matches the fleet's "derive, don't hardcode" toolchain
  convention applied to a systemd unit's spawn PATH.
- *=make doctor='s secondary reachability check reports INFO, not FAIL*, when
  the XDG_RUNTIME_DIR-default path is unreachable — that is the expected,
  healthy state in a correctly-configured deployment, and styling it FAIL
  would read as broken exactly when nothing is wrong. Added a =statusInfo=
  level matching =mcp-gql-kit/cmd/mgk/doctor.go='s own four-way status shape.
- *The end-to-end probe uses a FIXED fixture directory*, not a fresh temp dir
  per run, so repeated =make doctor= calls within the broker's idle window
  reuse an already-warm pyright session instead of leaving a new orphaned
  process each time.
- *Probe position is always derived from =documentSymbol='s SelectionRange,
  never hand-picked* — this is the structural fix for the null-response
  ambiguity (mcp-ast todo =714a9133=), applied on the diagnostic side only;
  no mcp-ast code was touched.

* Glossary
- consumer path :: the socket path mcp-ast/ae actually dial, given their
  real mgk-filtered spawn environment (neither XDG_RUNTIME_DIR nor TMPDIR
  set) — see design doc §4
- divergence :: broker listening at one candidate socket path while every
  real consumer dials a different one
- SelectionRange :: the LSP DocumentSymbol field naming the exact identifier
  span for a symbol; the only sound source for a diagnostic probe position
- warm session :: an already-initialized language-server process the broker
  keeps alive between queries, keyed on (projectRoot, language)
