* Session Topic
Implement mgmt 6131a2a1: org-lsp, a pure-Go, Emacs-free org-mode LSP server,
using the org module's orgast engine behind lspbridge's existing symmetric
jsonrpc substrate. Decide and document the module-home tradeoff (lspbridge's
root must stay zero-dependency), ship a small honest v1 capability surface,
and prove it end to end — not just unit tests, the real compiled binary.

* Decisions Made
- *Nested Go module, not a root-module package.* lspbridge's zero-dependency
  invariant (no go.sum) is load-bearing across several prior sessions; a
  subdirectory with its own go.mod is invisible to the parent module's
  build (=go list ./...= from root excludes it entirely), so this is the
  only way to add an orgast dependency without poisoning every consumer of
  pkg/jsonrpc/pkg/lsp. Verified, not assumed: root go.sum absence
  reconfirmed after landing this on main.
- *Relative replace directive for the unpublished parent.* Root lspbridge
  has no git remote (verified: =git remote -v= empty) so a nested module
  cannot =require= it via the proxy. =replace github.com/davidwalter0/lspbridge
  => ../= plus a placeholder pseudo-version is the standard Go workaround —
  and not improvised here: go-autocfg/vaultsource already does exactly this
  in this same GOPATH, for the identical reason.
- *github.com/davidwalter0/org v0.1.0 needs no replace* — it IS tagged and
  published, and was already present in the local module cache (confirmed
  a full offline =GOPROXY=off go build ./...= before depending on it), so a
  plain =require= was correct and simpler.
- *The position-oracle split (orgast=semantics, lineindex.go=positions).*
  go-org v1.9.1 has zero position tracking on its AST — discovered by
  reading its actual struct definitions (Headline, Block, Drawer — no Pos/
  Line field anywhere), not assumed. Rather than forking/patching orgast or
  go-org, org-lsp re-derives positions independently via small line-
  oriented regexes matching the same syntax tokens go-org's own lexer uses,
  then ALIGNS that scan against orgast's semantic lists by document order +
  (level, text-containment) matching — never by raw index (fragile) and
  never by re-deriving crypt/PGP logic (orgast already owns that
  correctly; duplicating it would be a fork-of-truth smell).
- *Src blocks nest into the DocumentSymbol tree via a synthetic level*, not
  a separate attach-children pass: a src block is assigned
  (enclosing-heading-level + 1) and merged into the SAME line-sorted,
  level-keyed stack-build as headings, so it nests exactly like a deeper
  sub-heading would. This also fixed a Kind-consistency issue: a heading
  with no sub-heading but ONE src-block child (e.g. "Implementation" in the
  test fixture) must still render Kind=Namespace, not String — Kind is
  computed from the FINAL rendered children count, not a heading-only peek.
- *Kind mapping for headings (documented, not hidden): Namespace if it has
  any children (heading or src-block), String if it's a leaf.* LSP has no
  purpose-built "outline heading" kind; this is the closest sensible,
  explicitly documented stand-in per the todo's own instruction to "pick
  sensible values and document."
- *Unimplemented methods return a real JSON-RPC MethodNotFound*, not a
  silent =null= success — stricter than the fakelsp test-fixture precedent
  (which is fine as a test double, not as the contract for editors that
  will actually probe capabilities).
- *Exit-code fidelity*: shutdown-then-exit -> process exit 0; exit without
  a prior shutdown -> exit 1, per the LSP spec's Exit Notification section
  (verified via a direct curl+grep of the spec HTML, not recalled).
- *Coverage scope matches the sibling root Makefile's convention*: =make
  cov= scans =./pkg/...= only, excluding =cmd/= — the root lspbridge
  Makefile already established this (cmd/fakelsp, cmd/lspbroker aren't
  coverage-scored either), so org-lsp's Makefile follows the same local
  norm rather than introducing a different one.

* Glossary
- position oracle :: this session's term for pkg/orglsp/lineindex.go — the
  file that reconstructs line/Range information orgast/go-org never track
- level-sorted stack build :: the single algorithm ([[file:pkg/orglsp/symbols.go][buildSymbolTree]]) that
  nests both headings and src-block leaf symbols by comparing outline level
- org-lint-lite :: org-lsp's one diagnostics pass: broken file: links +
  unclosed #+begin_ blocks, nothing heavier
- strata boundary :: the syntax-vs-behavior line this project draws
  everywhere org is involved — orgast/org-lsp own syntax, real Emacs owns
  behavior (babel, agenda, formulas)
